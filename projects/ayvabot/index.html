AyvaBot

A personal multi-agent assistant that also works unprompted

A personal assistant I use every day. You talk to one main agent, which hands the work to specialist agents, each defined as a markdown file, and reports back. It also works without being asked: scheduled agents, a 30-minute heartbeat, reminders and a morning plan reach my phone on Telegram. It runs on my own machine and starts at login.

Private repo

No hosted demo: it works with my own mailbox, calendar and accounts, so it runs on my machine only. The repository is private because it holds personal data.

01 / The problem

Most agent demos are a single prompt with a few tools. A useful assistant has to be several things at once: some agents that run on a schedule without being asked, some that need my approval before they act, and all of them honest about what they did not manage to do. I wanted to build that orchestration layer myself, so that adding a new agent means writing a markdown file rather than code.

02 / What it does

  • A main agent routes each request to one of 22 specialist agents, or to several at once, and relays the specialist's answer back
  • Agents are markdown files: description, mode, schedule, allowed tools and instructions; edit one and it applies immediately
  • 44 tools, each agent limited to its own allow-list: web search and fetch, GitHub, email, calendar, reminders, job search, news digest and memory
  • Proactive by design: a daily plan at 07:30, a 30-minute heartbeat that messages Telegram only when something needs attention, reminders and a weekly self-report
  • Every outward action reaches the phone with Approve and Dismiss buttons and the exact content; the card warns if web or email content was read first
  • Quick capture: send the Telegram bot a photo of a notice or a short note and it is read, filed and given reminders
  • An outreach agent drafts personalised recruiter emails, never guesses an address, avoids repeats with a log and waits for approval
  • Answers built from web, news, email or GitHub content go through a fact-check pass that removes claims the evidence does not support
  • Free model tiers first, then the Claude Code CLI on my own subscription, with usage and cost logged per agent against a monthly budget
  • A job hunter that reads company job feeds with no model in the loop, scores fit with rules, saves roles to a tracker and chases follow-ups

03 / How it works

Agents as data, not code

Each skill is a markdown file with a header — name, description, mode, schedule, the tools it may use, how many steps it gets — and the instructions as the body. Skills are re-read on every request, so editing one changes behaviour straight away, and adding an agent is adding a file. The main agent sees the catalogue of descriptions and decides who gets the work; delegation is itself a tool, capped at three levels deep so agents cannot call each other in circles.

Making a weak model fail honestly

Cheaper models skip the tool and improvise. A skill can declare tools it must call before it answers; if the model tries to finish without one, it is sent back with the exact call to make, up to twice, and if it still does not, the run ends with an error that says nothing was produced rather than returning an invented result. This came from a real failure: a calendar agent once answered without calling its tool and invented three reminders.

Spending nothing when there is nothing to do

Scheduled agents run a cheap check in plain code first and skip the model entirely when there is nothing to report. A LinkedIn drafting agent used to spend six model calls to conclude there was no update, because no token was connected; a readiness check now ends that run immediately with a plain message. When every tool reports nothing new, the agent returns “no update” instead of producing something to say.

Proactive without being noisy

A heartbeat written as ordinary code, with no model call, runs every 30 minutes and sends one Telegram digest of whatever needs attention: a calendar event within 90 minutes, approvals waiting more than three hours, new job matches scoring 8 or more, important unread email by simple rules, and applications with no reply after six days. It stays quiet from 22:00 to 07:00 while reminders still fire, and it remembers what it has already told me, so each thing arrives once. The daily plan at 07:30 is the same kind of tool.

Grounding, untrusted data and approval

Before an answer built on web, news, email or GitHub content is shown, a second pass checks every factual claim against what the tools returned, removes what is unsupported and says how many items it removed. Tool output, emails and fetched pages are wrapped as untrusted data, and an approval card carries a warning when the run read outside content before proposing the action. Scheduled agents act with nobody watching, so outward actions are parked as pending approvals and sent to my phone, where I approve or dismiss them. Autonomy covers planning and reading; consequence stays with me.

Capture from the phone

Sending a photo of a notice or a plain-text note to the Telegram bot starts a small pipeline: a vision-capable model reads the image, the main agent files the result with the right agent, and reminders are scheduled ahead of the dates it found. In a test, one note became two items and five reminders in 29 seconds, and reading a photo took about 8 seconds; the test data was removed afterwards.

Outreach with guard rails

The outreach agent drafts personalised emails to recruiters, but it can only use an address that appears on a public page or that I type myself. When I tested it, it searched a company's site, found no public address and declined to guess one. It checks a log so nobody is contacted twice, drops the draft in the Inbox with an Approve button, and does not read LinkedIn profiles because that is blocked and against the site's terms.

One model layer, free first

Gemini, Grok and Groq are tried first; when they fail or their free quota runs out, the call falls back to the Claude Code CLI on my own subscription, restricted to Sonnet and Haiku, with no API key stored. Each agent can state its preferred model, any message can pin a specific one, and a low-effort setting plus a few start-up flags made each CLI call roughly two to three times faster in my measurements. Every call is logged with its agent, tokens and cost, and a monthly budget pauses paid models when it is reached.

Searching jobs without a model

The job hunter does not ask a model to find jobs, because a model can invent a role that does not exist. It reads the public job feeds of more than fifty companies, filters for AI-engineering titles in the cities I would work in, drops anything already seen, and scores fit with plain rules for role match, seniority and location. Every result comes from the company's own feed, so it is real and open. A model is used only afterwards, to tailor a résumé or cover letter for a role.

Measured, then fixed

I timed every agent with side-effect-free prompts before tuning anything. The main agent answers in about 8 seconds, most specialists in 7 to 15, the fact-checking ones in 21 to 30, and the agents that write whole illustrated documents take up to about 95. The benchmark exposed a design bug: a simple greeting to the main agent took 171 seconds because it was forced to call a tool and ran a full briefing. Removing that requirement brought it to 8 seconds. Fact-checking also ran on every answer, and now runs only on answers built from outside content.

Running it like a service

The desktop app and the Telegram bot both start at Windows login as scheduled tasks. A scheduler thread ticks every 30 seconds and runs whatever is due. Every chat and scheduled run is logged, failures go to a separate error log, and a health check sends one Telegram alert a day if a scheduled agent keeps failing or the app stops. A daily backup zips the data and agent definitions to a cloud folder without the API keys, and a weekly self-report summarises activity, errors and usage.

Known gaps, stated

It is a single-user tool: the local server has no login because it listens only on my machine, and state lives in JSON files rather than a database. Its email, calendar and LinkedIn integrations are built but depend on credentials I have not all connected yet, so those paths are not exercised daily. There is a benchmark and UI scripts but no unit-test suite. Free-tier quotas often run out, which is why the subscription fallback exists, and weaker models follow tool instructions less reliably, which is why the required-tool check exists.

04 / Run it locally

  • ›The repository is private, so there is nothing to clone; ask me for a live walkthrough
  • ›Send /plan on Telegram for today's plan, or /news for the five best unseen AI items
  • ›Ask for new AI-engineering roles: the job hunter reads feeds and saves them to the tracker
  • ›Ask it to draft a recruiter email and watch it stop for approval, showing the exact content
  • ›Open Usage to see tokens and cost per agent against the monthly budget

05 / What I took away

  1. 1.An orchestrator is mostly guard rails: allow-lists, required tools, depth limits and approval gates matter more than the prompts.
  2. 2.Measure every agent before tuning: a greeting that took 171 seconds was a design bug, not a slow model.
  3. 3.Do not use a model for a job a plain feed and a few rules can do; it removes the risk of invention and the cost.
  4. 4.Proactive does not have to mean noisy: one digest, quiet hours and remembering what was already said.
  5. 5.Treat everything a tool returns as data, never as instructions.
  6. 6.Put agent behaviour in files a person can read and edit; it makes the system easier to trust and to change.
