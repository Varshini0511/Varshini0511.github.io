RAG document Q&A with a ReAct agent — on .NET

Upload a document and ask questions about it. A ReAct agent reasons step by step, searches the document semantically, and answers strictly from what it retrieves — with the entire pipeline written in C# rather than Python.

01 / The problem

Practically every RAG tutorial is Python. But my professional depth is .NET, and enterprises running on C# still need document Q&A. I wanted to prove the whole pipeline — chunking, embedding, vector retrieval, agent loop — works just as well in ASP.NET Core, with no Python service hiding in the middle.

02 / What it does

  • Full RAG pipeline in .NET 8 Web API — chunking, embedding, retrieval and generation in C#
  • ReAct loop: Thought → Action → Observation → Final Answer, with typed tools
  • Gemini gemini-embedding-001 producing 768-dim vectors stored in pgvector
  • Top-3 nearest-chunk retrieval by cosine distance; answers grounded in retrieved text only
  • Supports .txt, .md and .pdf with client-side chunking at ~800 characters
  • Server-sent-events streaming endpoint for token-by-token responses

03 / How it works

Grounding by construction

The agent answers only from chunks it retrieved. If the document doesn't contain the answer, there's nothing in the observation to answer from — so hallucination is prevented structurally rather than by asking the model nicely not to make things up. Cosine distance decides relevance: 0.0 is identical meaning, 1.0 is unrelated.

Two tools, deliberately

GetChunkCount runs a SQL COUNT for questions about the corpus itself; SearchDocuments embeds the query and searches pgvector for content questions. Keeping the tool surface tiny makes the agent's choices easy to reason about and easy to debug — most wrong answers trace back to a wrong tool choice, and with two tools that's immediately visible.

Clean service layering

AgentService owns the ReAct loop and tool execution, EmbeddingService owns Gemini calls and pgvector save/search, and the controllers stay thin HTTP adapters. It's the same dependency-injection discipline I use in enterprise .NET work, applied to an AI pipeline — which is precisely the point of building it in C#.

05 / What I took away

  1. 1.RAG is architecture, not a library — nothing about it requires Python.
  2. 2.Chunk size is a real tuning knob: too small loses context, too large dilutes the match.
  3. 3.A small tool surface makes agent behaviour far easier to debug.
  4. 4.Streaming changes perceived latency more than any backend optimisation did.
